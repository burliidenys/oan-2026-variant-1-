Сценарій SQLi:
мета: Отримати список усіх імен користувачів (таблиця users) та їхніх ID, використовуючи лише поле пошуку заявок.


IDOR:
Вразливість тут у тому, що контролер бере id з URL і відразу передає його далі, не ідентифікуючи користувача, який робить запит.
Вразливість виникає через те, що бекенд-логіка не перевіряє приналежність ресурсу (ID 10) користувачу, який ініціював запит. Відсутність перевірки ownerUserId дозволяє будь-якому автентифікованому (або навіть неавтентифікованому) користувачу видаляти чужі дані».
 

Щоб виправити вразливість IDOR, потрібно впровадити три рівні захисту: ідентифікацію користувача, перевірку існування запису та перевірку прав власності.
 


Stored XSS:
Cross-Site Scripting (XSS) — це вразливість, яка виникає, коли шкідливий JavaScript-код зловмисника потрапляє на бекенд, зберігається в базі даних та без перевірки повертається іншим користувачам. Виправлення її у файлі request.service.ts за допомогою функції escapeHTML, яка перед виведенням даних автоматично перетворює небезпечні символи на нешкідливий текст (HTML-ентіті).
 


Misconfiguration:
Під час відправки некоректного POST-запиту (без обов'язкового поля userName) додаток продемонстрував уразливість Security Misconfiguration. Сервер повернув клієнту повне трасування стеку помилок (Stack Trace) у форматі HTML. Це дозволяє зловмиснику дізнатися внутрішню структуру каталогів сервера, назви файлів та архітектуру коду. Крім того, у відповіді присутній заголовок X-Powered-By: Express, який розкриває технологію бекенду, спрощуючи хакеру пошук специфічних експлуатацій для цієї платформи.

Через те, що в коді немає кастомного мідлвару для обробки помилок, Express при будь-якому збої (наприклад, коли ти не передав userName) автоматично використовує свій вбудований обробник. Саме він і генерує ту HTML-сторінку з повним Stack Trace та твоїми локальними шляхами до папок.

Для усунення уразливостей Security Misconfiguration та харднінгу сервера було встановлено модуль Helmet.js, який автоматично приховує заголовок X-Powered-By: Express та налаштовує безпечні заголовки захисту від клікджекінгу й MIME-атк. Також впроваджено сувору політику CORS для обмеження міжсайтових запитів лише довіреним доменом фронтенду, а сирі HTML-помилки зі Stack Trace замінено на безпечний централізований ErrorHandler, що повертає виключно очищений JSON із коректними HTTP-кодами.

Завдяки інтеграції глобального мідлвару errorHandler, додаток повністю приховав внутрішній трасування стеку (Stack Trace). Сервер повернув відповідь у чистому, безпечному JSON-форматі з коректним кодом стану 400 Bad Request та часовою міткою. Крім того, підключення пакета helmet дозволило видалити заголовок деструктивної розвідки X-Powered-By: Express та активувати захисні заголовки браузера.
